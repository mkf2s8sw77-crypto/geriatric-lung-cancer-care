# LLM Prompt：geriatric-lung-cancer-care Phase 2/4

## 阶段目标

在 P1 稳定底座上交付患者/家属移动 Web App 与护士移动工作站的全病程护理闭环：患者完成任务、宣教和主动症状报告，护士完成预警处置、随访、干预和护理路径的人工调整。所有动作真实落库并可追溯。

## 本阶段输入

- 必读 `AGENTS.md`、Master Spec、当前 P2 文档和 test case，均位于项目根目录及 `promptDocs/prompt-pack-geriatric-lung-cancer-care-0812/`。
- 已完成前序阶段：P1 应已有 Next.js、basePath、品牌、SQLite/Drizzle、鉴权/RBAC、seed/reset、建档开户及最小评估预警闭环。
- 开始前检查 P1 代码和 migration，运行 `npm run db:reset && npm run lint && npm run typecheck && npm run test && npm run build`；若失败，先做阻塞本阶段的最小修复。
- 不依赖 P1 会话记忆；以仓库现状、Master Spec 和测试文档为事实源。

## 任务清单

1. **完善患者移动端导航与首页**
   - 在 `390×844` 优先视口实现首页、任务、宣教、趋势和个人信息导航；单手可达、点击区至少 44×44 像素。
   - 首页真实查询今日评估、待办/逾期任务、最近风险提示、责任护士和推荐宣教；支持加载、空、错误和成功状态。
   - 所有患者查询在服务端限定当前患者 ID，不能靠客户端参数决定访问对象。

2. **完善症状评估的老年友好能力**
   - 优化分步表单：大字号、高对比、大按钮、明确进度、上一题/下一题、自动保存、恢复草稿、提交确认和重复提交防护。
   - 使用浏览器原生 `speechSynthesis` 朗读当前题目；无支持时优雅隐藏/禁用并给出文字反馈，不引入外部语音服务。
   - 结果页展示总分、主要症状、风险等级和趋势，但明确为演示评估、需医护复核。

3. **主动症状报告**
   - 患者选择症状、0—10 严重度、发生时间并填写备注；校验未来时间、空内容和重复点击。
   - 中/高程度按演示规则生成护士预警；患者端展示及时就医/联系护士提示，不输出诊断。
   - 护士患者时间线和预警列表同步显示来源为“患者主动报告”。

4. **任务中心与护理路径实例**
   - 落实评估、随访、用药、复诊、康复、宣教六类任务的计划、状态和反馈。
   - 患者可提交完成、未完成、暂不适用；操作幂等，逾期由日期和状态计算，不依赖外部定时任务。
   - 将 seed 的 3 套路径实例化为患者任务；保留模板版本与患者分配记录。
   - 系统可以基于风险显示“建议增加复评”等提示，但绝不能自动新增、修改或取消任务。

5. **健康教育**
   - 实现患者分类列表、详情、阅读进度/确认和语音朗读。
   - 护士可从已启用资源中给患者分配宣教，查看已读/未读；首期不做上传和外链媒体。
   - 使用本地文本、图标和 CSS 卡片表现内容；除医院 Logo 外不增加图片。

6. **患者趋势**
   - 展示近 30 天总分、主要症状和任务完成率，支持无数据和少数据状态。
   - 图表使用本地包或 SVG/CSS；可访问文字摘要必须与图表一致，不能只靠颜色表达风险。

7. **护士移动工作站**
   - 工作台展示负责患者、今日随访、未处理预警、逾期任务和快捷入口。
   - 患者列表支持关键词、风险、治疗阶段、随访状态筛选；患者详情整合档案、评估趋势、任务、预警、宣教、随访和时间线。
   - 护士可代填评估或确认患者自评，记录来源、操作者和时间。
   - 预警详情显示触发依据，支持确认、忽略、升级；要求填写处理摘要，支持电话联系、护理指导、建议就医和复评时间。
   - 随访支持新建、编辑未提交记录、提交和设置后续任务；干预闭环能回看。

8. **人工护理路径调整**
   - 护士从患者详情查看当前路径和系统建议，手动新增/编辑/暂停/取消单个未来任务。
   - 强制填写调整原因；在事务内写任务变更和审计，保留前值、后值、操作者和时间。
   - UI 明确显示“系统不会自动调整，需护士确认”。不要实现自动任务重排、定时 AI 决策或后台 job。

9. **补齐演示数据**
   - Seed 达到 Master Spec 要求的患者任务、主动报告、预警、随访、干预和宣教数量。
   - 固定 `patient_demo` 在今日有评估、用药、康复和宣教任务，且有历史趋势；固定 `nurse_demo` 有待处理高风险和今日随访。

10. **移动端测试**
   - 增加任务状态、主动报告、预警、人工调整和患者数据隔离的单元/集成测试。
   - 安装并配置 Playwright Chromium 官方版本；移动项目命名为 `mobile-chromium`，viewport 固定 `390×844`，`workers:1`。
   - E2E 覆盖患者评估/任务/宣教/报告和护士预警处置/人工调整；测试创建独立 browser context，不复用用户 Chrome。

## 范围边界

### 本阶段要做

- 患者与护士的所有移动端核心业务，以及它们之间的数据闭环。
- 老年友好、语音朗读、自动保存、数据隔离、操作审计和移动 E2E。

### 本阶段不要做

- 不做管理员量表/路径/规则 CRUD 页面、科研驾驶舱/导出、完整审计浏览和 AI 分析工作台；这些属于 P3。
- 不做最终截图、用户手册和全站视觉收口；这些属于 P4。
- 不做自动护理路径调整、真实消息推送、外部 AI、文件上传或院内接口。

## 实现约束

- 任何患者 ID、任务 ID、预警 ID 都要结合 session 在服务端做对象级权限判断。
- 所有变更要支持重复点击/重试，不产生重复任务、预警或干预记录。
- 语音只在用户点击后触发，组件卸载/切题时停止；不得自动播放。
- 护士移动端不是压缩版 PC 表格；优先卡片、筛选抽屉和固定主要动作。
- 不用 Emoji、外部图片、外链字体或 CDN；Logo 保持完整比例。

```bash
npm run db:reset
npm run lint
npm run typecheck
npm run test
npm run build
npm run test:e2e -- --project=mobile-chromium
```

人工检查：

- 在 `390×844` 完整走患者评估、草稿恢复、主动报告、任务反馈、宣教朗读和趋势。
- 在 `390×844` 完整走护士患者搜索、预警处置、随访、宣教分配和手动任务调整。
- 验证患者 A 无法通过 URL/请求访问患者 B；护士无法访问管理员配置。
- 确认移动页面无横向滚动、按钮不拥挤、Logo 不变形、红色只用于风险/错误。
- 确认浏览器 console 无未处理异常，关键请求无 4xx/5xx 或 basePath 404。

## 完成标准与交接

- 患者异常报告 → 护士预警 → 人工处置 → 手动调整未来任务 → 患者看到新任务的完整链路可复现。
- 移动 E2E 稳定通过，seed reset 后仍可重复。
- 给 P3 留下清晰领域服务、配置版本引用、稳定演示数据和已验证的移动路由；交接时列出 P3 尚需实现的管理配置、统计、导出、审计和 AI mock。
