# LLM Prompt：geriatric-lung-cancer-care Phase 3/4

## 阶段目标

在已完成的患者/护士闭环上交付护士管理员 PC 端、可配置业务规则、科研统计/脱敏导出、完整审计和本地确定性 AI 演示能力。阶段结束时，系统功能范围应基本冻结，只剩 P4 的跨角色验收、修复、截图和用户手册。

## 本阶段输入

- 必读 `AGENTS.md`、Master Spec、当前 P3 文档和 test case。
- 已完成前序成果：P1 工程/数据/鉴权/评估，P2 患者和护士移动全病程闭环。
- 运行全量 P1/P2 门禁，检查实际 schema、权限和 seed；若有阻塞，只做必要修复，不重写已验证架构。
- 本阶段不得假设有正式临床量表、风险模型或 AI Key，所有智能能力均使用 Master Spec 确定的演示配置。

## 任务清单

1. **管理员 PC 信息架构与驾驶舱**
   - 在 `1280×800` 优先实现品牌顶栏、可折叠侧栏、面包屑和稳定内容区。
   - 驾驶舱真实统计患者状态、治疗阶段、风险分布、今日评估、任务完成率、未处理预警和近 30 天趋势。
   - 指标卡和图表可点击进入对应筛选列表；空数据、加载、错误状态完整。

2. **患者与人员管理**
   - 管理员查看全量患者、分配责任护士、变更研究状态；高风险/退出等关键操作有确认与审计。
   - 管理管理员、护士和患者账号的启停、密码重置、显示名和最近登录；不能读取或导出密码哈希/session。
   - 护士端已有建档能力继续复用同一服务，避免两套不一致逻辑。

3. **量表版本管理**
   - 实现量表列表、查看、新建草稿、编辑题目/分值/顺序、校验、发布、停用和复制版本。
   - 产生评估数据的已发布版本不可原地修改；发布新版本后，新建评估引用新版本，历史评估继续引用旧版本。
   - UI 明确提示演示量表并允许未来替换，不宣称正式临床量表。

4. **护理路径版本管理**
   - 管理路径名称、适用治疗阶段、相对天数、任务类型、标题、说明和启停；支持复制版本与发布。
   - 新版本不自动覆盖已在路径中的患者；管理员/护士必须显式分配或选择是否应用。
   - 不实现自动随风险重排任务。

5. **预警规则版本管理**
   - 配置单项阈值、总分阈值、较上次增量和任务逾期规则，提供业务校验和预览。
   - 已生效规则版本不可原地改变历史含义；新评估使用当前发布版本，预警记录保存触发规则快照/依据。

6. **宣教资源管理**
   - 管理标题、分类、治疗阶段、摘要、正文、语音可读状态、启停和排序。
   - 首期只编辑文本，不实现上传、图片、视频或外部链接；除 Logo 外页面不展示图片。

7. **确定性 AI 演示分析**
   - 实现 `mock-geriatric-lung-v1` 领域服务：根据最高症状、总分、较上次变化、任务依从性和治疗阶段生成固定结构结果。
   - 输出包括症状摘要、主要风险因素、建议护士复核项、建议随访时间、患者易懂提示和免责声明。
   - 同一输入同一输出；支持护士采纳/部分采纳/不采纳并备注，记录版本和输入依据。
   - 在患者详情/预警详情显示 AI 演示分析，但患者端只显示经过安全措辞的简化提示，不直接展示内部建议。
   - 不发出任何网络 AI 请求；测试需断言 `AI_MODE=mock` 且无 provider 配置也能工作。

8. **科研统计与脱敏 CSV**
   - 真实数据库聚合：纳入/完成/失访/退出，随访时间点完成率，症状均值趋势，风险分布，任务完成率，预警处置时长和路径执行。
   - 支持治疗阶段、风险、责任护士、日期范围筛选；无结果时清楚反馈。
   - CSV 使用 UTF-8 BOM 和稳定中文表头；只含研究编号、允许的人口学分组、评估、任务、风险、干预等字段。
   - 明确排除姓名、电话、登录账号、密码哈希、session、自由文本中可能含身份信息的备注；导出动作写审计。

9. **审计日志**
   - 提供管理员只读筛选页面，覆盖登录、建档、账号变更、患者变更、版本发布、预警处理、路径/任务人工调整、AI采纳和导出。
   - 审计摘要使用结构化 allowlist，禁止记录密码、token、Cookie、完整请求体和敏感自由文本。

10. **管理员端测试和 seed 收口**
   - seed 数据达到 Master Spec 所有数量要求，驾驶舱有稳定、非空且互相一致的数据。
   - 增加配置版本、AI 确定性、脱敏 CSV、审计 allowlist、管理员/护士权限的单元/集成测试。
   - Playwright 增加 `desktop-chromium` 项目，viewport `1280×800`，覆盖配置、统计、导出和权限。

## 范围边界

### 本阶段要做

- 完整管理员 PC 端、配置版本、AI mock、科研统计/导出、审计和桌面 E2E。
- 修复 P1/P2 中会影响最终一致性、权限或统计的数据问题。

### 本阶段不要做

- 不对接外部 AI、消息、院内系统或真实临床模型。
- 不做文件上传、自动路径调整、生产级患者数据迁移。
- 不提前制作最终用户手册截图；页面在本阶段可进行必要视觉完善，但最终稳定截图留给 P4。

## 实现约束

- 所有聚合和导出必须从数据库真实查询，不硬编码统计数字。
- CSV 导出与审计必须有服务端 ADMIN 权限；通过直接 URL 访问同样受保护。
- 配置采用版本化而非原地覆盖历史数据；发布/停用需要事务和审计。
- AI mock 逻辑与 UI 分离、确定性可测试；界面处处显示“演示分析、医护复核”。
- PC 表格提供分页/筛选和窄屏兜底，但主要验收为 `1280×800`。

## 验证要求

至少执行：

```bash
npm run db:reset
npm run lint
npm run typecheck
npm run test
npm run build
npm run test:e2e -- --project=desktop-chromium
```

人工检查：

- 在 `1280×800` 逐页访问管理员全部路由，执行新建/编辑/发布/停用/筛选/导出。
- 验证量表、路径、规则历史版本不可被误改；新版本不会自动覆盖历史患者任务。
- 下载 CSV，用文本/表格工具核对 UTF-8 中文、字段和脱敏，不出现姓名、电话、账号、哈希、token。
- 同一输入重复生成 AI 演示分析，结果一致；断网后功能仍可用且无外部请求。
- 使用护士/患者直接访问管理员 URL，确认服务端拒绝且无数据泄漏。
- 检查 Logo、布局、表格、图表、空态、弹窗和危险操作颜色。

## 完成标准与交接

- 所有产品功能范围完成并通过三角色权限和数据一致性检查。
- P4 可以只做全站验收、缺陷修复、稳定截图、手册和最终 production 启动，不需要再补主要功能。
- 交接时给出当前端口、seed 后关键统计、已知但不阻塞的演示临床配置声明和需要 P4 重点复核的页面。
