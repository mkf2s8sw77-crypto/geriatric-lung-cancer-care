# LLM Prompt：geriatric-lung-cancer-care Phase 4/4

## 阶段目标

对已经完成的系统进行最终质量收口：运行全量自动门禁，在隔离浏览器环境中逐角色、逐功能、双视口真实操作，修复发现的问题；随后生成稳定截图和面向客户的图文用户手册，复核所有引用与视觉效果，并以 production 模式在选定端口运行。

本阶段不是只“看看首页”，也不是重新扩展功能。完成标准是系统功能、权限、响应式、basePath、演示数据、截图和手册全部闭环。

## 本阶段输入

- 必读 `AGENTS.md`、Master Spec、当前 P4 文档和完整 test case。
- 预期前序成果：P1—P3 已完成所有主要功能；若实际缺失，先按 Master Spec 补齐阻塞验收的内容。
- 首选端口：`12168`；basePath：`/geriatric-lung-cancer-care`。
- 固定账号：`admin_demo`、`nurse_demo`、`patient_demo`，密码 `Demo@2026`。
- 可使用 `webapp-testing` 或 `playwright` 技能辅助真实浏览器验收；若使用，先完整读取对应技能说明并遵守其隔离规则。

## 任务清单

1. **冻结基线与端口安全检查**
   - 检查 Git 状态、`AGENTS.md`、环境、migration 和 seed；不要覆盖用户无关改动。
   - 运行 `npm run db:reset`，核对 Master Spec 规定的账号、数据数量和风险分布。
   - 用 `lsof -nP -iTCP:12168 -sTCP:LISTEN` 检查首选端口。若占用，不停止未知进程；在 10000—20000 选择空闲端口，并更新 `.env.local`、Playwright、`AGENTS.md` 和 run manifest 中的端口/URL。

2. **全量自动门禁**
   - 运行 lint、typecheck、所有 Vitest、production build 和 Playwright。
   - 检查 migration 从空数据库可执行，reset 连续执行两次结果一致，健康检查正确。
   - 将任何失败视为必须修复的问题，不通过跳过测试、弱化断言或硬编码结果解决。

3. **隔离的真实浏览器验收**
   - Playwright `workers:1`，使用项目专属 `.tmp/playwright-geriatric-lung-cancer-care-<port>` 和全新 browser context；禁止连接用户 Chrome profile。
   - PC 固定 `1280×800`，移动固定 `390×844`，禁止 full-page 长截图。
   - 按 test case 逐条执行三个角色所有功能，真实点击、填写、保存、刷新、筛选、下载和回看结果。
   - 逐路由检查加载、空、成功、校验失败、无权限、停用账号和重复提交；检查 console、network、资源 404、布局溢出和 focus/键盘操作。
   - 发现问题直接修复、补回归测试，再重新执行相关用例；最多进行 3 轮完整 smoke/fix。

4. **品牌和响应式收口**
   - 逐页确认医院 Logo 完整、比例正确、背景对比合适，桌面/移动均无裁切。
   - 患者和护士移动端落实大字号、大触控区、少层级、语音入口、状态反馈和无横向滚动。
   - 管理员端在 `1280×800` 下侧栏、表格、图表、弹窗和下载入口可用，不出现遮挡或内容越界。
   - 除 Logo 外不出现图片、远程资源或 Emoji；普通操作不滥用高风险红色。

5. **规划并采集用户手册截图**
   - 根目录创建 `screenshots/`，文件名使用稳定 ASCII，例如 `patient-home-mobile.png`、`admin-dashboard-desktop.png`。
   - 移动功能用 `390×844` 截图，PC 功能用 `1280×800` 截图；护士移动工作站同样用移动视口。
   - 每张图只截当前 viewport，`fullPage:false`；选择能完整表达该模块的稳定状态，关闭无关开发工具和临时提示。
   - 不截登录功能；截图不得显示演示密码、终端、技术栈或开发信息。
   - 至少覆盖：患者首页、评估、报告、任务、宣教、趋势；护士工作台、建档、患者详情、预警、随访、人工任务调整；管理员驾驶舱、量表、路径、规则、宣教、人员、科研统计/导出、审计。

6. **编写图文用户手册**
   - 创建且只创建 `docs/老年肺癌患者症状群智能评估与全病程管理系统概要设计 2026-08-12.md` 作为最终说明文档。
   - 文档 H1 必须是“老年肺癌患者症状群智能评估与全病程管理系统概要设计 2026-08-12”。
   - 不介绍登录，不写账号密码、技术栈、数据库、部署、测试、开发过程或系统架构。
   - 每个功能模块严格采用“标题＋一段不超过 100 个汉字的自然语言说明＋系统截图”。说明必须是自然段，不列点，从客户角度描述功能。
   - 全文使用全角中文标点；Markdown 语法标记和图片路径按语法保留，正文标点不混用半角。
   - 截图引用统一为 `../screenshots/<file>.png`，每个功能模块的截图必须直接对应正文。

7. **双重检查手册与截图**
   - 解析 Markdown 中全部图片引用，确认文件存在、路径大小写一致、无未引用的错误截图。
   - 使用图片尺寸工具确认每张图恰为 `1280×800` 或 `390×844`，不接受长截图或意外设备比例。
   - 逐张实际查看，确认 Logo、导航、标题、数据、弹窗、裁切、留白、风险色和隐私内容无问题。
   - 检查每个模块说明不超过 100 个汉字、没有列表、没有登录/技术栈/账号密码内容，并做半角中文标点漏检。
   - 若发现任一问题，重新进入正确页面截图并替换，直至引用和视觉全部通过。

8. **最终 production 运行**
   - 完成最终 `npm run build`，用 production 模式绑定 `127.0.0.1:<选定端口>` 启动。
   - 仅管理本项目自己启动且 PID 明确的进程；不使用 `pkill`、`killall` 或宽泛清理。
   - 验证 `<basePath>/api/health`、登录页和三个角色关键页；最终报告实际端口、进程状态、健康 URL 和门禁结果。
   - 若通过 `dev-with-prompt` runner 执行，由 manifest `[deploy]` 负责最终驻留进程时，本阶段先以临时受控进程完成浏览器验收并停止自己的临时 PID，避免双重占用。

9. **最终维护 `AGENTS.md`**
   - 只补充实际最终端口、稳定命令或真实架构变化等长期事实；删除过时规则，保持不超过 200 行。
   - 不创建 README、验收报告或实施总结 Markdown。

## 范围边界

### 本阶段要做

- 全量测试、真实浏览器操作、缺陷修复、响应式/品牌收口、稳定截图、客户用户手册、production 启动。

### 本阶段不要做

- 不新增超出 Master Spec 的业务模块，不接外部系统/AI，不改变人工路径调整原则。

- 不影响其他项目进程、端口、浏览器 profile、截图或 Playwright 会话。
